# 项目定稿说明

## 1. 当前系统已完成内容

当前版本已经完成以下内容：

- 产品、企业、批次三类后台基础管理
- 批次工作台聚合展示
- 现场录入、草稿保存、续写与提交
- 质检摘要上传与发布前校验
- 二维码生成、公开页预览与发布联动
- 消费者公开追溯页的正常码、风险码、无效码展示
- 风险处理链路（冻结、整改、恢复发布判断）
- 监管只读视角与写操作拦截
- 一键系统 smoke 回归与端口防污染启动脚本

## 2. 当前版本的主链路

当前版本的主链路为：

产品 -> 批次 -> 现场记录 -> 质检 -> 二维码 -> 发布 -> 公开追溯 -> 风险处理

后台以批次工作台为中心，公开页以消费者可理解的信息为中心，风险链路和监管链路作为主链路之外的重要异常与权限补充。

## 3. 当前版本的验证方式

推荐的一键回归命令如下：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-system-smoke.ps1 -SkipInstall
```

当前这套回归会自动：

- 检查并清理本工作区残留 demo 进程
- 启动 `backend(demo)`、`admin-web`、`trace-web`
- 执行 7 组核心 smoke/e2e，共 12 条用例
- 输出测试摘要
- 自动停止服务并回收端口

## 4. 已知但不阻断答辩的问题

当前已知但不阻断答辩的问题主要有：

- 前端仍存在大 chunk 打包告警，但不影响当前演示与功能稳定性。
- 部分历史文档和历史截图命名仍保留 round 前缀，适合在材料整理阶段统一归档。
- `trace-web` 中仍保留历史页面文件 `TraceView.vue`，当前路由未使用，不影响现行演示链路。
- 测试体系仍然依赖 demo 种子数据中的固定账号和固定批次，后续可以再做夹具化整理。

## 5. 明确不再继续修改的范围

从当前阶段开始，明确不再继续修改以下范围：

- 不再新增大功能
- 不再重构状态机
- 不再大改页面结构
- 不再大范围重做视觉风格
- 不再扩展角色体系或复杂权限模型
- 不再大规模调整 demo 数据结构

后续只建议做：

- 必要的材料截图补拍
- 文案整理
- 论文写作所需的结构化说明整理

## 6. 后续建议顺序

建议后续严格按以下顺序推进：

1. 材料整理
2. 论文撰写

材料整理阶段重点：

- 固定最终截图集
- 整理系统结构图、主链路图、角色图和测试结果摘要
- 准备答辩讲解口径

论文撰写阶段重点：

- 按系统定位、角色场景、业务闭环、实现方案、工程优化、测试验证、问题与展望展开
- 以当前稳定基线为准，不再引入新的系统变化
