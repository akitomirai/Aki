# 答辩备用材料与演示口径清单（第5包）

## 1. 答辩材料总原则

答辩演示必须与论文口径一致。论文正文、系统截图、测试材料和现场演示都应统一使用“农产品溯源管理信息系统”这一正式名称，避免在正式表述中混入项目代号式称呼。涉及本地页面或接口已有命名时，可以保留“公开追溯查询”“公开追溯端”等实现层面的功能词。

主演示链路必须固定。答辩时优先围绕主演示批次 `ORANGE-202603-D1`、主 token `orange-202603-d1`、主演示企业 `赣南果业种植有限公司`、主演示产品 `赣南脐橙` 展开。这样可以避免临场切换数据导致页面状态、截图、论文内容和测试材料不一致。

测试夹具、旧 `DEMO_FLOW` 和历史 token 不能混入主演示。`test-token-2026` 只能作为历史冲突或后端测试夹具说明，不能作为当前主演示公开地址。旧 `docs/DEMO_FLOW.md` 中的 `testuser1`、`test-token-2026`、`BATCH20260311001` 不应出现在答辩主线中。

“当前实现”和“扩展设计”必须分开说。当前实现优先依据 `schema-demo.sql`、`data-demo.sql`、controller、router、页面和最终 demo baseline；`docs/database/sql/01_schema.sql` 中的更完整 MySQL 结构只能作为扩展参考，不应混入当前实现主图、主截图和主演示流程。

## 5. 推荐的答辩演示顺序

### 5.1 开场 1 句话

固定说法：我设计并实现的是一个农产品溯源管理信息系统，核心是以批次为主线，把产品建档、现场记录、质检、二维码发布、公众查询和风险监管串成一条可演示的业务闭环。

### 5.2 后台演示顺序

1. 打开管理端 `http://127.0.0.1:5174/login`。
2. 使用 `platform / 123456` 登录。
3. 展示 Dashboard，说明系统整体运行视角。
4. 展示企业主体管理，说明企业是业务主体。
5. 展示产品建档，说明产品是批次创建的基础。
6. 展示批次列表，定位 `ORANGE-202603-D1`。
7. 进入 `/batches/2` 批次工作台，说明批次聚合状态、任务、质检、二维码和风险信息。
8. 简要展示现场填报入口 `/field-entry`，说明操作员负责过程留痕。
9. 展示 `/quality`，说明质检结果是发布依据。
10. 展示 `/qr`，说明批次与公开 token 绑定。

### 5.3 公开查询演示顺序

1. 打开 `http://127.0.0.1:5173/t/orange-202603-d1`。

3. 重点讲产品信息、批次号、企业信息、质检结论、追溯时间线和正常状态。

### 5.5 收尾 1 句话
