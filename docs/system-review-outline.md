# 系统梳理提纲

## 1. 系统定位

本系统面向农产品生产、质检、公开追溯和风险处置场景，解决的是“批次信息分散、追溯链条不清晰、答辩演示不稳定、角色协同成本高”的问题。系统希望用一条轻量、可闭环、可演示的业务链路，把产品、批次、现场记录、质检、二维码、公开追溯和风险处理串起来。

之所以选择“轻量级农产品追溯系统”，而不是做成复杂平台，是因为当前项目的重点不是覆盖庞大企业级协同能力，而是验证一条完整、清晰、可落地的核心业务闭环。轻量化的好处在于页面更聚焦、逻辑更容易解释、测试范围更可控，也更适合论文、答辩和后续逐步扩展。

## 2. 用户角色与使用场景

### 企业管理员

企业管理员负责维护产品与批次基础信息，补录或审核关键业务资料，上传质检摘要，生成二维码，完成发布，并在风险出现时执行冻结、召回和恢复发布判断。

### 现场操作员

现场操作员围绕被分配的批次执行现场记录补录、图片上传、草稿保存与续写，确保工作台和公开页能拿到关键追溯节点。

### 消费者

消费者通过扫码进入公开追溯页，快速查看产品来源、批次状态、质检结论和关键追溯过程，并在风险批次下看到明确提示。

### 监管人员

监管人员以只读方式查看批次、质检、风险和状态流转信息，不直接改写业务数据，而是从监管视角判断链路完整性与风险处置进度。

## 3. 核心业务闭环

系统核心闭环为：

产品 -> 批次 -> 现场记录 -> 质检 -> 二维码 -> 公开追溯 -> 风险处理

各环节系统职责如下：

- 产品：承载基础商品信息，是批次创建的前提。
- 批次：承载一次具体生产/流转实例，是后续所有追溯与风控动作的主对象。
- 现场记录：记录生产、运输、仓储、上市等关键节点，形成追溯过程主体。
- 质检：提供发布前的质量判断和公开可信依据。
- 二维码：提供公开入口，是后台和消费者查询链路的连接点。
- 公开追溯：面向消费者展示状态、质检和关键时间线，强调可理解性。
- 风险处理：处理冻结、召回、整改、恢复发布等异常链路，保证系统解释一致。

## 4. 系统当前的设计原则

当前系统设计原则主要体现在以下几个方面：

- 页面简洁：优先呈现当前任务、当前状态、推荐动作和必要说明，避免大表单和信息噪音。
- 逻辑简洁：批次状态流转有限且可解释，非法跳转会被前后端同时拦截。
- 使用流畅：主链路围绕“下一步该做什么”展开，弱化非关键操作。
- 防误操作：重要动作增加确认、禁用非法按钮、补齐校验和重复提交拦截。
- 可演示、可维护：页面信息分层明确，测试链路可复跑，脚本和文档能支撑答辩场景。

## 5. 已完成的工程优化总结

本轮前后端已完成的关键优化包括：

- 明确批次状态流转规则，前后端统一拦截非法状态跳转。
- 收口冻结/召回批次发布阻断提示优先级，统一 UI 提示、接口返回和测试断言。
- 对 RiskTodoView、QualityTodoView、FieldEntryView 做主按钮唯一化、推荐动作突出和次操作弱化。
- 抽离公共组件，如主动作按钮组和状态标签，减少重复实现。
- 补齐表单校验、防重复提交、空态/异常态展示和确认操作。
- 为公开页补充无效码友好错误态，让公开查询更贴近真实使用场景。
- 完成 7 组核心 smoke/e2e 串联，并提供一键回归入口。
- 完善启动与停止脚本，增加端口防污染逻辑，避免演示打到旧服务。

## 6. 当前仍保留的问题

### 收尾前必须处理

- 保持 demo 数据与测试脚本同步，避免后续调整 seed 后造成回归脚本失效。
- 持续约束新增页面沿用当前的主动作、状态流转和防误操作规范，防止收尾阶段出现风格回退。
- 在最终材料阶段固定答辩演示账号、演示批次和推荐展示路径，减少临场变量。

### 论文中可作为后续优化方向

- 增加更完整的自动化测试分层，如接口测试、视觉回归和更广覆盖的端到端链路。
- 进一步优化前端打包体积和加载性能，减少大 chunk 警告。
- 将 demo 数据种子和测试夹具进一步模块化，减少对固定批次和固定 token 的依赖。
- 引入更细粒度的状态机或流程配置能力，支持未来扩展更复杂的业务链路。

## 7. 后续阶段建议顺序

建议后续阶段按以下顺序推进：

### 收尾

先固定演示环境、账号、数据和回归入口，确保功能、测试和页面表现都稳定，再谨慎做必要的小修，不再引入大改动。

### 材料整理

整理系统结构图、角色流程图、核心页面截图、测试结果摘要和关键优化点，形成答辩和中期/终期材料的统一口径。

### 论文撰写

在论文中围绕“问题背景 -> 轻量化设计选择 -> 角色场景 -> 业务闭环 -> 系统实现 -> 工程优化 -> 测试验证 -> 局限与后续优化”展开，尽量让系统实现、测试验证和设计原则形成同一条叙述主线。
