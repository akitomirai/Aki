# 质检与风险处理设计

质检结论决定批次能否进入公开发布；风险处理决定异常批次能否冻结、召回或恢复。系统按“企业负责资料、平台可协助、监管只读复核、消费者只看公开结论”的方式控制。

## 使用角色

| 角色 | 使用目标 | 可操作范围 |
| --- | --- | --- |
| 企业管理员 | 上传本企业批次质检摘要、补充风险处置记录 | 只能管理本企业批次；可上传质检、冻结、召回、补整改并申请恢复 |
| 平台管理员 | 协助企业维护质检和风险闭环 | 可跨企业上传质检、处理风险状态和恢复发布 |
| 监管人员 | 查看质检结论、风险状态、处置过程和公开效果 | 只读，不上传质检，不改变风险状态 |
| 现场操作员 | 补录现场追溯事实 | 不上传质检报告，不处理风险动作 |
| 消费者 | 扫码查看公开质检摘要和风险提示 | 不进入后台，不查看内部处置明细 |

## 质检结论

| 结论 | 使用含义 | 发布影响 |
| --- | --- | --- |
| PASS | 合格，已形成可公开结论 | 可作为发布或恢复发布条件 |
| REVIEW | 待复核，检测结论尚未稳定 | 不允许发布或恢复发布 |
| FAIL | 不合格，需要先进入异常核查 | 不允许发布或恢复发布 |

## 风险处理

| 场景 | 处理动作 | 约束 |
| --- | --- | --- |
| 已发布批次发现异常 | 冻结或召回 | 需要写明原因，二维码公开页同步风险提示 |
| 冻结批次处置中 | 补处理说明、标记处理中、补整改记录 | 风险动作必须有原因或说明 |
| 冻结批次恢复 | 标记已整改后恢复发布 | 必须有处理说明或整改记录，并且最新质检为 PASS |
| 召回批次 | 持续补整改记录 | 不允许恢复发布 |

## 设计要点

1. 发布准入只认 PASS，不能把 REVIEW 当作“非失败”处理。
2. FAIL 和 REVIEW 都会阻断发布，但含义不同：FAIL 指向风险处理，REVIEW 指向复核补充。
3. 监管人员可查看全部批次的质检和风险状态，但任何写动作都会被拒绝并写入失败操作日志。
4. 现场操作员的责任是补录现场事实，不承担质检报告和风险状态决策。
5. 前端准备度、推荐动作和后端发布校验必须使用同一套规则，避免页面提示“可发布”但接口拒绝，或接口放行未复核批次。
