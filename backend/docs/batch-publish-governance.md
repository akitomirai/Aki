# 批次建档与二维码发布设计

批次是产品档案进入公开追溯前的业务载体，二维码是消费者访问公开页的入口。系统按“先建档、再补公开追溯、再质检、再生成二维码、最后发布”的顺序控制。

## 使用角色

| 角色 | 使用目标 | 可操作范围 |
| --- | --- | --- |
| 平台管理员 | 统一管理全平台批次与发布状态 | 可跨企业建批次、补追溯、上传质检、生成二维码、发布、冻结和召回 |
| 企业管理员 | 管理本企业批次从建档到发布 | 只能管理本企业批次，可分配现场操作员，可发布本企业批次 |
| 现场操作员 | 按分配任务补录现场追溯 | 只能查看和提交分配给自己的批次，不发布、不上传质检、不生成二维码 |
| 监管人员 | 查看批次、质量、风险和公开效果 | 只读，不改变批次、质检、二维码或风险状态 |
| 消费者 | 扫码查看公开追溯页 | 只能访问已发布、已冻结或已召回批次；草稿二维码不对外展示详情 |

## 发布准入

| 条件 | 原因 | 系统校验 |
| --- | --- | --- |
| 至少一条消费者可见追溯记录 | 避免空白公开页或只有二维码无追溯内容 | 发布接口和前端发布检查同时校验 |
| 已上传质检摘要且结论为合格 | 避免未质检、待复核或不合格批次对外发布 | 发布接口只放行 PASS 结论 |
| 已生成二维码 | 公开页入口与批次绑定后才能发布 | 发布接口要求二维码存在 |
| 风险状态已闭环 | 冻结批次恢复发布前必须有处理说明和整改完成记录 | 风险流转服务校验 |

## 二维码状态

| 批次状态 | 二维码状态 | 消费者访问 |
| --- | --- | --- |
| 草稿 | READY | 不展示公开详情，提示等待企业发布 |
| 已发布 | ACTIVE | 展示公开追溯、质检和企业信息 |
| 已冻结 | SUSPENDED | 继续展示公开详情，并突出风险提示 |
| 已召回 | RECALLED | 继续展示公开详情，并突出召回提示 |

## 管理流程

1. 平台管理员或企业管理员创建批次，批次必须挂到启用中的企业和产品。
2. 企业管理员分配现场操作员；现场操作员通过移动端补录关键追溯记录，至少一条记录应设置为消费者可见。
3. 平台管理员或企业管理员上传质检摘要和附件，质检不合格时不能发布。
4. 管理员生成二维码，二维码可用于内部核对和打印，但草稿状态扫码不会返回公开详情。
5. 发布接口再次校验公开追溯、质检、二维码和风险状态，满足条件后二维码转为 ACTIVE。
6. 发布后如发现风险，可冻结或召回；公开页保留消费者可见信息并展示风险处置状态。
