# 公开反馈处理设计

公开反馈连接消费者扫码页和后台处理台账。系统按“消费者提交、系统归属、企业处理、平台兜底、监管只读”的方式闭环。

## 使用角色

| 角色 | 使用目标 | 可操作范围 |
| --- | --- | --- |
| 消费者/采购商 | 在公开追溯页提交信息不一致、质量疑问、二维码异常等问题 | 匿名提交，不选择企业和权限；产品、批次、追溯码由当前扫码页带入 |
| 企业管理员 | 处理本企业产品和批次的公开反馈 | 只能查看和处理已明确归属本企业的反馈，关闭时必须填写处理结果 |
| 平台管理员 | 分拣无法归属的反馈，处理跨企业和系统级问题 | 可查看和处理全部反馈，负责未关联企业反馈的兜底处理 |
| 监管人员 | 复核公开反馈和企业响应 | 可查看全部反馈，不允许修改处理状态 |
| 现场操作员 | 执行现场补录任务 | 不进入反馈处理模块 |

## 归属规则

| 反馈来源 | 系统处理 | 管理责任 |
| --- | --- | --- |
| 追溯码可匹配二维码 | 以二维码绑定批次为准，覆盖前端提交的产品名和批次号 | 对应企业管理员处理，平台可协助 |
| 追溯码缺失但批次号可匹配 | 以批次档案为准，补齐企业和产品信息 | 对应企业管理员处理，平台可协助 |
| 追溯码和批次号均无法匹配 | 保留用户提交信息，不分配企业 | 仅平台管理员处理，监管人员可查看 |

## 处理闭环

| 状态 | 使用含义 | 约束 |
| --- | --- | --- |
| 待处理 | 用户刚提交或平台待分拣 | 企业只能看到已归属本企业的记录 |
| 处理中 | 企业或平台已接手核对 | 可填写当前处理进展 |
| 已处理 | 已完成核对、解释、整改或关闭 | 必须填写不少于 10 个字的处理结果 |

## 设计要点

1. 公开提交不要求消费者注册，避免扫码反馈门槛过高。
2. 企业管理员不能看到未归属反馈，避免把无法确认责任主体的信息暴露给所有企业。
3. 后端以追溯码和批次档案重新解析产品、批次、企业，避免前端传参被伪造后污染处理台账。
4. 监管人员只能查看处理过程和结果，不能代替企业或平台修改反馈状态。
5. 管理端列表突出责任主体，详情页展示处理人和处理时间，便于后续复核。
