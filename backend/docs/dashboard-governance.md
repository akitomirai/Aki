# 数据统计分析设计

数据统计分析不是录入入口，而是给不同管理角色判断“当前系统是否形成可公开追溯闭环”的工作台。使用边界按“平台全量调度、企业本域跟进、监管只读复核、现场不看后台统计”划分。

## 使用角色

| 角色 | 使用目标 | 可操作范围 |
| --- | --- | --- |
| 平台管理员 | 查看全平台产品、批次、发布、扫码、质检和风险情况，并导出统计备份 | 可查看全量统计，可导出平台范围备份 |
| 企业管理员 | 查看本企业批次发布进度、扫码效果、待质检和风险状态 | 只能查看本企业统计，可导出本企业范围备份 |
| 监管人员 | 只读复核公开发布、质检结论、风险批次和扫码使用情况 | 可查看全平台统计，不导出备份，不修改业务数据 |
| 现场操作员 | 补录现场追溯事实 | 不进入统计分析页，不查看跨批次经营统计 |

## 统计口径

| 指标 | 口径 |
| --- | --- |
| 产品总数 | 当前账号可见范围内的产品档案数量 |
| 批次总数 | 当前账号可见范围内的批次数量 |
| 已发布 | 状态为 PUBLISHED 的正常公开批次 |
| 已冻结/已召回 | 状态为 FROZEN 或 RECALLED 的异常公开批次，单独计入风险，不再重复计入未发布 |
| 未发布 | 批次总数减去正常发布和冻结/召回批次 |
| 扫码次数 | 优先使用二维码累计 PV；当查询日志数量更大时使用日志数量，保证演示数据和运行数据一致 |
| 备份企业数 | 平台视角统计全部企业；企业视角至少包含当前企业，即使还没有批次也能体现备份归属 |

## 设计要点

1. 统计读取和备份导出不是同一权限：监管人员可以看统计，但不能导出备份。
2. 企业管理员所有统计和备份都必须落在本企业范围内，不能出现其他企业名称或批次。
3. 风险批次是公开异常状态，不应同时被当作“未发布”重复计算。
4. 前端入口要和后端权限一致：监管账号不显示备份/导入按钮，后端仍会拒绝直接调用。
5. 备份导入只用于本地预览和核验，不覆盖现有业务数据。
